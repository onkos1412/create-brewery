# Toasts and Treating Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players clink drinks to get a toast bonus (longer effects, half hangover), and brewers are credited when others drink their signed drinks.

**Architecture:** Pure rules in `social/ToastRules` (bonus math); a `brewery:toast` mob effect as the visible marker; an `EntityInteract` handler for clinking; `DrinkItem.finishUsingItem` applies the bonus and the treat credit; `HospitalityData` SavedData tracks drinkers per brewer and pending awards, granted on login.

**Tech Stack:** NeoForge 1.21.1, Java 21, JUnit 5, GameTests, Python+Pillow.

**Spec:** `docs/superpowers/specs/2026-11-14-toasts-design.md`

- Toast bonus: effects ×1.5, hangover debt halved (rounded down); marker consumed by the drink; muddy/spoiled drinks: no bonus, marker still consumed.

## Review Focus

1. Clinking with an empty hand or with a non-drink item does nothing (no marker, no sound) — Task 1 test.
2. The marker expires after `toastSeconds` without drinking → next drink gets no bonus — Task 1 test (short window via config or direct effect duration).
3. Drinking your own drink never credits you; the same friend drinking twice counts once — Task 2 test.
4. An offline brewer's pending award is granted on next login and only once — Task 2 test via the login handler method called directly.
5. `toastBonus=false`: no duration/hangover change, but the `toast` advancement still awarded — Task 1 test.
