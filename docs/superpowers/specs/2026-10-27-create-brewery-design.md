# Дизайн: Create Brewery — аддон варения алкоголя для Create

## Намерение и зачем

Сделать мод-аддон для Create (NeoForge 1.21.1), который переносит варение
алкогольных напитков из плагина BreweryX в мир жидкостей и машин Create.
Игрок строит конвейер из нагретых бассейнов, миксеров, котлов, бочек и
розлива, и получает напитки с качеством и эффектом опьянения.

Ключевое отличие от простого набора рецептов: процесс **можно сделать
идеально, а можно испортить**. Правильно собранная и настроенная контрапция
стабильно даёт высший сорт; ошибка в настройке — хуже качество или порча.

## Цели / не-цели / анти-цели

**Цели:**
- Полная система варения: варка → перегонка → выдержка → розлив, не все шаги
  обязательны для каждого напитка.
- Качество со шкалой 1–5 звёзд, зависит от точности каждого шага.
- «Идеальная настройка = всегда идеальный результат»: точность задаётся
  RPM + температурой + временем, подбирается передачами/нагревом.
- Полная система опьянения: заплетающаяся речь в чате, искажение экрана,
  отключка (потеря управления) при передозе — как в BreweryX.
- Процесс автоматизируется средствами Create (трубы, насосы, контрапции).

**Не-цели:**
- Не точный клон всех рецептов BreweryX; делаем свой набор напитков-примеров,
  расширяемый через datapack JSON.
- Не поддержка других версий MC/лоадеров (только NeoForge 1.21.1).
- Не ванильная замена зелий; опьянение — отдельная механика.

**Анти-цели (что сделает мод провальным, даже если технически работает):**
- Качество, которое невозможно стабильно получить идеальным (механика должна
  быть детерминированной и поддаваться настройке).
- Свои машины, которые «выпадают» из Create и не работают с его трубами/нагревом.

## Ограничения

- NeoForge 1.21.1, Java 21, Gradle + официальный шаблон ModDevGradle.
- Зависимость от Create (maven `com.simibubi.create:create-1.21.1`).
- Нагрев в Create задаётся источником тепла (Blaze Burner и пр., уровень
  `HeatLevel`); вращение — кинетической сетью (RPM). Наши машины читают эти
  значения извне, а не изобретают свой источник энергии.
- Рецепты — через собственные `RecipeType`/`RecipeSerializer` + datapack JSON,
  чтобы сервер/сборки могли добавлять напитки без правки кода.

## Подходы (рассмотрены и почему выбран A)

**A — свои машины-блоки (кипятильня, перегонный куб, бочка, розлив).**
Полный контроль над таймингом/RPM/нагревом и качеством. Больше кода.
**B — поверх родных блоков Create (Basin/Mixer/Tank/Spout) без своих.**
Максимально «Create», но читать RPM миксера и нагрев бассейна извне через
публичный API Create неудобно и ненадёжно — механика получится «дырявой».
**C — гибрид (минимум своих блоков, качество «приклеено» к жидкости).**
Меньше кода, но всё равно нужен обход ограничений API; контроль хуже.

**Выбрано A**: ядро мода — точность/провал, а это честно реализуется только в
своих блоках, где мы владеем таймингом, RPM и нагревом целиком.

## Решение «как» (что зафиксировано с заказчиком)

### Столпы
1. **Идеальная настройка = идеальный результат.** Каждый шаг имеет «окно
   идеала» по времени и температуре (и, где применимо, RPM миксера). Попадание
   в окно даёт высший балл за шаг. Всё детерминировано — правильно собранный
   конвейер всегда даёт 5 звёзд.
2. **Качество 1–5 звёзд.** Напиток получается всегда (шаги дают продукт), но
   итоговый рейтинг — агрегат точности всех шагов. Низкий рейтинг добавляет
   негативные эффекты к напитку.
3. **Полная система опьянения.** Накапливающийся уровень алкоголя: лёгкое
   опьянение → заплетающаяся речь (чат) → искажение экрана → отключка при
   передозе (жёсткая потеря управления, как в BreweryX). Вытрезвление со временем.

### Шаги процесса (свои машины)
- **Варка** — «Кипятильня» (нагреваемый бак с миксером): вода + ингредиенты →
  сусло. Учитывает нагрев (HeatLevel) и время. RPM миксера влияет на
  равномерность (качество).
- **Перегонка** — «Перегонный куб» (нагретый котёл с трубой на выходе): сусло →
  дистиллят. Критичен нагрев и время (недогрев — слабо, перегрев/передержка —
  порча).
- **Выдержка** — «Бочка» (жидкостный бак с типом дерева): дистиллят/сусло
  выдерживается N игровых дней. Не то дерево или слишком долго — порча/снижение.
  **Тип дерева задаётся крафтом/предметом** (одна модель бочки; игрок
  кладёт внутрь доску/материал нужного дерева, который определяет дерево).
  **Время выдержки — как в BreweryX**: 1 «год» = 1 игровой день (daylight
  cycle); сон/перемотка времени ускоряют выдержку.
- **Розлив** — «Носик» (совместимый с механикой spout Create): жидкость →
  бутылки с напитком, каждая несёт свой рейтинг качества.
- Не все напитки проходят все шаги — в рецепте указано, какие нужны.

### План первой итерации (скелет)
Сначала собираем **скелет насквозь**, прежде чем наращивать:
одна машина + один напиток, проходящий весь путь «варка → розлив в бутылку →
опьянение», чтобы проверить всю архитектуру (свой блок/BE, рецепт, качество,
розлив, система опьянения). После рабочего скелета наращиваем: остальные
машины (перегонка, выдержка), набор напитков, полная шкала качества.

### Механика качества
- Каждый шаг даёт «балл точности» в зависимости от близости к идеальному
  окну (время/температура/RPM). Итог = среднее/минимум по шагам → 1–5 звёзд.
- Порча (полный выход за окно на перегонке/выдержке) даёт «испорченный» напиток
  с сильными негативными эффектами, а не просто 1 звезду.

### Данные напитка
- Напиток = жидкость + метаданные качества. Розлив превращает жидкость в
  бутылку-предмет, сохраняя рейтинг звёзд (NBT/компоненты данных 1.21.1).
- Эффекты напитка и сила опьянения задаются в рецепте.

## Что оставлено строителю (мои решения, отмеченные как мои)

- Точные числовые окна идеала (секунды/уровень нагрева/RPM) для каждого шага —
  подбираю сам, сбалансировав под ощущение «настраиваемости».
- Конкретный набор напитков-примеров (примерно 5–8: пиво, вино, виски, медовуха,
  ром и т.п.) с разными комбинациями шагов.
- Точный набор негативных эффектов на низких звёздах и силы опьянения.
- Названия блоков/предметов/жидкостей и текстуры/модели (заглушки на старте).
- Детали API-интеграции с Create (как именно читаем HeatLevel и RPM — через
  публичные классы `IHeatLevel`/кинетический BE).
- Названия блоков/предметов/жидкостей и текстуры/модели (заглушки на старте).
- Точные числовые окна идеала, список напитков, негативные эффекты, сила
  опьянения.

## Объём

Полный проект: свой набор блоков с BE, свои рецепты, система качества,
система опьянения, розлив, datapack-расширяемость, набор напитков.
Оценочно — многофайловый мод с несколькими пакетами (блоки, BE, рецепты,
эффекты, опьянение, клиент).
