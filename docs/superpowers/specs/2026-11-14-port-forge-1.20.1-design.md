# Port to Minecraft 1.20.1 Forge — design

## Intent
Publish Create Brewery on Modrinth for more players. Create 6 exists only for 1.21.1 NeoForge (done),
1.20.1 Forge (Create 6.0.8) and 1.20.1 Fabric (Create Fabric 6.0.7/6.0.8). 1.19.2 and older only have Create
0.5.1 and are out. The user chose **both 1.20.1 targets**; this document covers **Forge first**, Fabric gets its
own design afterwards.

## Goals
- Full feature parity with `main` (1.21.1) as of commit eb229a6: kettle, distillery, barrel, spout, keg, mugs,
  all drinks and recipes, quality, drunkenness (sway, slur, stagger, vomit, pass-out, hangover), drink effects,
  brewer signature, brewer's book (journal, binding, exclusive payload, screen), toasts and treating,
  advancements, server config + config screen, Ponder scenes, JEI optional, art and lang unchanged.
- Same mod id `brewery`, package `com.kostya.createbrewery`, same assets; same behaviour and numbers.
- All unit tests and all game tests ported and passing on 1.20.1 (Forge GameTest server).
- Release jar `create-brewery-<version>+mc1.20.1-forge.jar`, tested in a real 1.20.1 client (screenshots).

## Non-goals
- New features while porting; Fabric (next design); NeoForge 1.20.1 as a separate build (Create 1.20.1 runs on
  both, so the Forge jar may work there, but it is not a promised target).

## Decisions (designer's calls; the user handed over the how)
- **Separate branch, separate worktree:** `mc1.20.1-forge` branched from `main`, in its own git worktree, so the
  1.21.1 code on `main` stays untouched. Later fixes are carried between branches by hand/cherry-pick.
- **Toolchain:** ForgeGradle 6 (the standard for 1.20.1), Forge 47.x, **Java 17**. No JDK 17 is installed; Gradle's
  toolchain resolver downloads Eclipse Temurin 17 on the first build.
- **Dependencies:** Create `com.simibubi.create:create-1.20.1:6.0.8-<build>:slim` plus the exact Ponder, Flywheel
  and Registrate versions Create 6.0.8's own POM names; JEI for 1.20.1 optional.
- **API translation** (the bulk of the work):
  - Data components (`DRINK_DATA`, `BREWER`, `BOOK_OWNER`) → item/fluid **NBT**, behind small accessor helpers
    with the same names, so game logic stays readable and close to `main`.
  - Data-pack folders back to 1.20.1 names (`recipes`, `advancements`, `loot_tables`, `tags/items|blocks`), recipe
    JSON result format of 1.20.1, `RecipeHolder` → `Recipe` with ids.
  - Networking: Forge `SimpleChannel` for the book payload.
  - Capabilities: Forge `ICapabilityProvider`/`getCapability` on block entities instead of NeoForge capability
    registration.
  - Events/registries/config: Forge equivalents (`ForgeConfigSpec`, `DeferredRegister`, `MinecraftForge.EVENT_BUS`).
  - Mob effect `toast`, SavedData, attachments (drunk level, hangover, stagger position) → Forge capabilities or
    persistent player NBT.
- **Versioning:** the next release is **0.2.0** on every target (the Unreleased changelog becomes 0.2.0).

## Approaches considered
- **Branch per target (picked):** simplest, each branch is an ordinary single-loader mod; cost: fixes must be
  ported by hand.
- Multi-loader single codebase (Architectury / common module): one place for logic, but Create's APIs differ
  between loaders and versions, so most code would still be per-platform, and the restructuring is large.

## Left to the builder
- Exact Forge, Registrate, Ponder, Flywheel, JEI versions (match Create 6.0.8's POM).
- How each NeoForge-only API maps to Forge, test by test.
- Order of porting (suggested: build setup → registries/items/blocks → data → machines → drunk/effects → journal/
  book/network → toasts/treating → client/Ponder → tests green → client check → release jar).
